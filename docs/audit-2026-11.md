# Audit, November 2026

A full read of `src/`, `tests/`, the docs and the skills, against `main` at `1d29552`. Every
finding below was reproduced against `tests/mock_engine.py` (never the real engine) unless it says
otherwise. Line numbers refer to `1d29552`.

Severity: **High** can hurt ears, speakers or a mic, or defeats a documented safety promise.
**Medium** gives a wrong answer or a wrong write in a realistic setup. **Low** is polish, drift or
hardening.

## High

### H1. Talkback stays open when the MCP session ends

`__main__.py:295-299`. `serve()` runs the server in one event loop (`server.run("stdio")`) and
cleans up in a second one (`asyncio.run(_shutdown(...))`). When the client disconnects, the first
loop cancels the talkback auto-off task before it fires, and `_shutdown` only cancels it again.

Failure case: `uad_talkback(on=true)`, then close Claude Desktop within 30 s. `TalkbackOn` stays
`true` on the engine with no timer behind it: a live mic into the cue mixes until someone notices.
Reproduced: `TalkbackOn` reads `true` after shutdown.

### H2. The panic button is rate-limited

`safety.py:486`, `server.py:1122`. `uad_safe_state` goes through `check_write`, which charges the
token bucket. The bucket is empty exactly when an agent has been firing writes, which is when the
panic button is needed.

Failure case: with `UAD_MCP_WRITES_PER_SECOND=1`, `UAD_MCP_WRITE_BURST=2`, three fader writes then
`uad_safe_state()` returns `ok: false` and the monitor is not muted. The talkback auto-off write and
its retries hit the same limiter.

### H3. Concurrent monitor writes can beat the +10 dB / 30 s budget

`safety.py:533` and `safety.py:569`, `server.py:939`. The rolling window is computed from a single
shared `_last_monitor_db` that every check overwrites. MCP requests are handled concurrently
(`mcp/shared/jsonrpc_dispatcher.py` spawns one task per request), so two `uad_set_monitor` calls can
interleave read, check, write and record.

Failure case: monitor at -30 dB. Call A asks for -24, call B reads the level after A's write but
before A is recorded, and asks for -18. Both pass the budget check against an empty window, and A
records +0 dB because B overwrote the baseline. +12 dB lands inside a window that allows +10, and
the window shows only +6, so a third call can add more.

### H4. Clock and sample-rate gates fail open when no meter can be read

`server.py:322-342`. `audio_flowing()` treats "no meter values at all" as silence. `poll_values`
only raises when nothing answers; error replies count as answers and are dropped.

Failure case: on a model or engine version where `meters/N/MeterLevel` errors or is missing,
`audio_flowing()` returns `(False, -77.0, None)` and `uad_set_clock(..., confirm=true)` re-locks the
chain mid-take. Reproduced by removing `MeterLevel` from the fixture.

### H5. `full` mode can reach the monitor level around the rail

`safety.py:103-121`, `server.py:1986`. The README and the `uad_raw_set` description promise the
monitor rail still applies in `full` mode. It only checks `CRMonitorLevel`.

Failure cases, all accepted by the gate in `full` mode:

- `uad_raw_set(path=".../outputs/22/CRMonitorLevelTapered", value=1.0)` is 0 dB on the monitor.
- `uad_raw_set(path=".../outputs/22/SurroundTrimLevel", value=10)` adds up to +10 dB of trim.
- `uad_raw_set(path=".../outputs/22/Mute/value", value=false)`: the rail looks for
  `.../Mute/CRMonitorLevel`, does not find it, and treats the strip as an ordinary output.
- Denylist matching is exact and case-sensitive: `//pluginscenes/...`, `/PluginScenes/...` and
  `multiunitorder` all pass. Whether the engine resolves those spellings is unverified, so the gate
  should not depend on it.
- `uad_raw_set(path="/TalkbackOn", value=true)` opens talkback with no auto-off timer.

## Medium

### M1. Multi-device meter results merge channels with the same name

`server.py:1778` (and `audio_flowing`'s `where`). `uad_watch_meters` keys `peaks_db` and
`triggered_channels` by `channel.name`. Two cascaded x8s both have `ANALOG 1`, so their peaks merge
into one entry and a trigger on device 1 reads as device 0. The derived cascade fixture prefixes
device 1 names with `"B "`, which is why the suite never saw it.

### M2. A numeric `device` string matches device names before indices

`discovery.py:318-344`. `device="2"` is tried as a name substring first, and `"Apollo x8 Gen 2"`
contains `2`, so it selects device 0. With a cascade of `Apollo x16` units, `device="1"` matches all
of them. MCP clients often send numbers as strings.

### M3. Tool failures are not flagged as errors at the MCP layer

`server.py:196`. The `tool` wrapper turns exceptions into `{"ok": false, "error": ...}`, which MCP
returns with `isError: false`. Clients and models that key on `isError` see a refusal or an
unreachable engine as a success.

### M4. Unknown item keys are silently ignored in batch tools

`server.py:726`, `server.py:894`. `uad_set_channels(items=[{"target": "KICK", "name": "KICK IN",
"volume": -6}])` renames the channel, ignores `volume`, and reports `ok: true`. A model's typo looks
like a success.

### M5. `uad_set_sample_rate` and `uad_set_clock` say `ok: true` for an unverified write

`server.py:1171`, `server.py:1252`. If the engine reports a different value after the write (it
silently rejected or quantized it), `ok` is still `true`. AGENTS.md rule 5 says `verified: false` is
a failure.

### M6. `auto_off_s=0` turns the talkback timer off

`server.py:1105`. Any value of 0 or below disables the timer, while the tool description promises
"an open talkback mic cannot be forgotten". Nothing documents the zero case.

### M7. Tool schemas carry no enums or hints

`server.py:2144` onwards. `kind` is a free string (the allowed values, including `"all"`, are only
in SPEC), and no tool declares MCP `annotations` (`readOnlyHint`, `destructiveHint`), so clients
cannot auto-approve reads or flag writes.

## Low

### L1. One malformed frame drops the whole socket

`client.py:295`. A bad frame raises inside the reader, every pending request fails and the socket
reconnects. NUL framing resynchronizes on its own, so skipping the frame is enough.

### L2. A late reply can satisfy the next request for the same path

`client.py:385-404`. With no correlation IDs, a reply that arrives after its request timed out is
taken by the next waiter for that path. The worst outcome is a read up to one timeout old. This is a
protocol limit; documented here, not changed.

### L3. `mcp` has no upper bound

`pyproject.toml:18`. `mcp>=2.0` will pick up a future 3.x. The `FastMCP` fallback in
`server.py:2127` is dead code under that pin, because `FastMCP` takes no `version` argument.

### L4. Docs drift

- README says the default `addopts` is `-m 'not live'`; it is `-m 'not live and not slow'`, and the
  slow soak test is not mentioned.
- Test counts change with this audit (README, CHANGELOG).
- `uad_set_monitor`'s description does not say that `level_db` above the ceiling is refused, not
  clamped.

## Not changed: needs a decision from Phil

- **Headphone and cue levels are unrailed.** Send `Gain` goes to +12 dB, preamp `Gain` to +65 dB,
  `FaderLevel` to +12 dB and `TalkbackMaster` to 100, and `HP n` outputs can be unmuted freely. A
  performer's headphones get no ceiling. A rail like the monitor's would need numbers only Phil can
  pick.
- **Talkback timer upper bound.** `auto_off_s=3600` is accepted. Should there be a cap?
- **`Enable24dBMode`, `AltMonSelection`, `MixToMono`.** All can change acoustic level. Left alone.
- **Panic button in `readonly` mode.** `uad_safe_state` is refused in `readonly`, matching "nothing
  is written, ever". Arguably the one write that should always work.

## Could not verify without hardware

- Whether the engine resolves `//`, case-variant or `/value/value` paths (H5 closes them anyway).
- That the real engine needs no extra handling for the shutdown talkback-off write (H1).
- Cascade behaviour on real multi-unit hardware (M1, M2 are mock-tested).

## Status

Fixed on `audit-improve`, each with a test: H1 to H5, M1 to M7, L1, L3, L4. L2 is a protocol limit
and stays documented. The read-only `--check` doctor ran cleanly against the live engine (UAD
11.9.0, Apollo x8 Gen 2); nothing was written to it.
